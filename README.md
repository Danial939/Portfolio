# Портфолио Даниила Бондарева

React + TypeScript + Vite, Tailwind CSS (базовые стили), Framer Motion, Lucide React.

## Запуск

```bash
npm install
npm run dev
```

## Проверка и сборка

```bash
npm run typecheck   # tsc --noEmit
npm run build       # typecheck + vite build
npm run preview
```

## Что исправлено

- **Сборка.** Версии зависимостей зафиксированы (раньше стояло `latest`), добавлены `@types/react` и `@types/react-dom`, из-за которых падала типизация.
- **Шрифты.** Kanit не содержит кириллицы, поэтому русский текст рисовался системным шрифтом. Теперь заголовки — Unbounded, текст — Golos Text (оба с кириллицей).
- **Фонарик.** Световое пятно переписано: тёмная страница, мягкий свет в центре, плавное затемнение к краям. Координаты пишутся напрямую в CSS-переменные через rAF с сглаживанием. Отключён на тач-устройствах и при `prefers-reduced-motion`.
- **Этапы работы.** Прогресс привязан к положению таймлайна относительно центра экрана и сглажен пружиной. Процент и активный этап берутся из одного значения, поэтому они всегда совпадают. Вертикальная линия заполняется вместе с прогрессом. Плашка «Готовность проекта» липкая: на десктопе справа, на мобильных — полоса вверху.
- **Технологии.** Сфера стала настоящей 3D-сферой: точки распределены по поверхности, вращаются мышью или пальцем с инерцией, медленно дрейфуют сами, пока раздел в кадре. Категории подсвечивают свои технологии на сфере.
- **Контакты.** Элементы появляются при прокрутке. Заголовок — «Давайте обсудим ваш проект». Контакты — плейсхолдеры в массиве `contactLines` в `src/App.tsx`.
- **Нумерация разделов** совпадает с ТЗ: 03 — Технологии, 04 — Этапы, 06 — Контакты.
- **Доступность.** Размеры текста увеличены (минимум 11px для подписей, 15–16px для основного текста), контраст поднят, добавлены `:focus-visible`, `aria-expanded` у меню, `MotionConfig reducedMotion="user"` для Framer Motion.

## Перед публикацией

1. Подставить реальные контакты в `contactLines` (`src/App.tsx`).
2. Заменить три карточки в `projectCards` реальными проектами и ссылками.
3. Проверить `techGroups` — каждая технология должна соответствовать вашему реальному опыту.
4. Настроить тексты в `steps` и `services`, если они не совпадают с вашими процессами.
